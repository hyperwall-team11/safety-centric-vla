# 최종 발표용 물류창고 시연

금속 랙 사이의 자재 공급 구역에서 `amr-01`이 부품 상자와 팔레트를 싣고 출발합니다. 검사 스테이션까지의 8 m 운반 통로에서 AMR의 x 좌표가 −2.4 m를 지나면 작업자가 선반 사이에서 나와 한 번 횡단합니다. CCTV 02에서 나온 실제 RGB 프레임을 RT-DETR에 입력하고, 검출한 작업자의 발 위치를 고정 카메라 보정값으로 바닥에 투영합니다. 두 연속 프레임에서 보행자 진입부를 관측하면 기존 CV 경로로 위험 이벤트를 등록합니다. 보행자 진입부 감시 영역은 AMR 차선 중심에 접근하기 전의 횡단 구역입니다. 기존 경로의 금지구역 판정과 검출 신뢰도 기준을 적용합니다.

## 처음 한 번 준비

ROS 2와 MuJoCo는 `control/pixi.toml`의 기존 환경을 사용합니다. Node.js, `uv`, Chromium 및 Three.js 에셋이 필요합니다. 창고는 기존 작업자 에셋과 적재 AMR 제어 코드를 사용하므로 로봇 팔 모델 4종의 별도 다운로드는 필요하지 않습니다.

저장소 루트에서 아래를 실행합니다.

```bash
cd control
pixi install --frozen
uv pip install --python "$PWD/.pixi/envs/default/bin/python" \
  --target "$PWD/outputs/warehouse-deps" -r ../backend/requirements.txt torch 'transformers<5'
cd scripts/threejs_cctv
npm ci
pixi run --manifest-path ../../pixi.toml python fetch_assets.py
npx playwright-core install chromium
cd ../..
```

Chromium을 자동으로 못 찾으면 `CHROMIUM_PATH`에 실행 파일의 절대 경로를 지정합니다. RT-DETR은 첫 실행에 공개 가중치를 받습니다. 발표장 인터넷 연결이 없어도 같은 사용자 계정의 캐시나 `WAREHOUSE_CV_MODEL`에 지정한 로컬 모델 폴더가 있으면 실행할 수 있습니다. 기본 모델은 `PekingU/rtdetr_r18vd`, 기본 추론 장치는 CPU입니다. 검증한 Mac에서 기본 모델은 기존 관측 최신성 조건을 충족했습니다. NVIDIA 환경에서 CUDA PyTorch를 설치했다면 `WAREHOUSE_CV_DEVICE=cuda`를 지정할 수 있습니다.

## 시작과 초기화

`control` 폴더에서 실행합니다.

```bash
PYTHONPATH="$PWD/outputs/warehouse-deps${PYTHONPATH:+:$PYTHONPATH}" pixi run warehouse-demo
```

같은 체크아웃의 다른 ROS 노드와 겹치지 않도록 시연은 기본 도메인 73 및 로컬 주소에서 실행합니다. 화면 `http://127.0.0.1:5181`, Backend `8017`, MJPEG `8081`, 사전 시뮬레이터 `8100`, 렌더 브리지 `8765`를 사용합니다. 터미널에 출력된 로그 폴더와 화면의 **시연 준비 완료**를 확인합니다. 영상이 보이고도 준비가 늦으면 `detector.log`의 모델 로딩과 `backend.log`의 작업자 스냅샷 등록을 확인합니다.

초기화할 때는 실행 터미널에서 `Ctrl-C`를 눌러 종료한 뒤 같은 명령을 실행하고 페이지를 새로고침합니다. 매번 새 메모리 Backend, 신규 시뮬레이션 상태와 로그 폴더를 사용합니다. AMR은 공급 구역의 적재 상태로 돌아가며 작업자 횡단을 다시 시작할 수 있습니다.

설치된 별도 ROS 환경을 재사용하려면 시연 스크립트에 `WAREHOUSE_ROS_PREFIX`를 지정합니다. 이 경우도 코드와 장면은 현재 체크아웃에서 읽습니다.

## 발표 순서와 멘트

1. **CCTV 01 · 운반 통로**를 크게 둡니다. “자재 공급 구역의 AMR에는 부품 상자가 실려 있습니다. 검증을 통과한 뒤 검사 스테이션으로 출발합니다.” 기본 입력인 `부품 상자를 실은 로봇을 "검사 스테이션"으로 이동해`를 제출합니다. 현재 파서는 따옴표로 감싼 구역명과 이동 동사를 지원합니다. 화면의 `MOVE_TO`, 목적지, 사전 시뮬레이션 근거를 확인합니다.
2. **CCTV 02 · 작업자 횡단 구역**을 크게 전환합니다. “작업자는 AMR이 지정 위치에 도달하면 선반 사이에서 나옵니다. 화면의 상자는 해당 프레임에서 RT-DETR이 검출한 작업자입니다.” 화면의 이름과 `T+` 경과 시각을 보며 운반 통로의 사건을 따라갈 수 있습니다. **CCTV 03 · 출하 도크**에서 랙과 도크를, **CCTV 04 · 후방 보관 구역**에서 추가 작업자 3명을 보여줍니다.
3. **CCTV 01**에서 정지 위치를 가리킨 뒤 **AMR CAM**을 확대합니다. “검출, 위험 판정, E-Stop 신호와 정지 확인은 실제 로그 순서입니다. 시뮬레이터의 선속도와 각속도가 정지 범위에 들고 어댑터가 `ESTOP`으로 바뀐 것을 확인했습니다.”
4. 작업자가 통로를 다 벗어난 뒤 **운영자 확인 및 위험 해제**를 누릅니다. “운영자 확인 뒤 E-Stop 신호는 해제됩니다. 현재 Backend에는 승인된 `RESUME` 발행 경로가 없어, AMR은 `ESTOP` 상태를 유지합니다.” 장면 초기화는 다음 회차 재현에만 사용합니다.

## 검증 기록

`control/outputs/warehouse.*` 아래의 `detections.jsonl`은 프레임 시각·좌표·신뢰도·위험 ID를, `telemetry.jsonl`은 실제 ROS 정지 신호·어댑터 상태·시뮬레이터 오도메트리를 기록합니다. 검출 프레임의 `T+`는 브리지의 시뮬레이션 시각이며, 이벤트 목록은 각 수신·판정 시각을 UTC에서 화면의 로컬 시각으로 변환해 정렬합니다. 위험 이벤트를 생성한 프레임은 `hazard-*.jpg`로 남깁니다.

2026-11-25 Apple Silicon 환경에서 세 카메라 RGB 영상, 실제 CV 모델과 ROS 2 경로를 사용했습니다.

| 회차 | 최초 검출 KST | 위험 판정 KST | E-Stop 수신 KST | 정지 확인 KST | 정지 x / 선속도 |
|---|---|---|---|---|---|
| 1 | 19:51:49.597 | 19:51:50.992 | 19:51:50.994 | 19:51:51.011 | −1.395 m / 0.000 m/s |
| 2 | 19:52:53.275 | 19:52:54.085 | 19:52:54.086 | 19:52:54.111 | −1.561 m / 0.000 m/s |

두 회차 모두 출발 전 사전 시뮬레이션을 통과했고, 주행 중 선속도가 0.400 m/s에서 E-Stop 후 0.000 m/s로 바뀌었습니다. 시뮬레이터 각속도도 0.000 rad/s였고 작업자가 통로를 벗어난 뒤 운영자 위험 해제가 성공했습니다. 회차별 로그는 `control/outputs/warehouse.vZ1fcR/`과 `control/outputs/warehouse.wKP0Ak/`에 있습니다. 브라우저에서 세 영상과 카메라 전환도 확인했습니다.

**운영자 확인 이후 연속 운반과 상자 도착은 실제 연동에서 미검증입니다.** Backend에서 승인된 재개와 정지 작업 정리 및 최신 위치를 반영한 새 명령의 발행 경로가 필요합니다. CTL 테스트에서는 계약에 맞는 승인된 `RESUME`과 새 이동 명령을 입력했을 때 적재 상자가 검사 스테이션 도착 허용 범위에 도달하는 것을 확인했습니다.

자동 테스트는 CTL 213개, CV 78개, Backend 278개가 통과했습니다. Backend 4개는 테스트 환경 조건으로 건너뛰었습니다.

### 시각 개선 후 재검증

랙 가새와 번호판, 상자 테이프와 물류 라벨, 천장 보와 조명, 셔터, 콘크리트 이음매를 추가했습니다. CCTV 01에서 천장과 출발 지점이 함께 보이도록 조정했습니다. 영상 크기는 640×480이며 Apple Silicon에서 카메라당 약 3–4 fps로 렌더했습니다.

최종 개선본은 2026-11-25 20:01:50.196 KST에 작업자를 검출했고, 20:01:51.794에 위험을 판정했습니다. 20:01:51.799에 ROS E-Stop을 수신하고 20:01:51.809에 x=−1.412 m, 선속도 0.000 m/s를 확인했습니다. 작업자가 통로를 벗어난 뒤 운영자 위험 해제도 성공했습니다. 로그와 검출 프레임은 `control/outputs/warehouse.imZNcl/`에 있습니다.


### 창고 확장과 출하 도크 카메라

창고 실내를 약 23 × 15 m로 넓혔습니다. 랙은 3열 12개 구획으로 배치했고, 끝 벽에 셔터 3개와 출하 대기 구획을, 도크 옆에 검수대를 추가했습니다. CCTV 01은 입구 쪽에서 운반 통로와 도크를 넓게 보고, CCTV 03은 도크 쪽에서 반대 방향을 봅니다. 작업자 검출 입력은 CCTV 02입니다. 도크 대기 구획에는 부품 상자를 실은 `amr-02`와 `amr-03`이 정차해 있습니다. 자연어 운반 명령과 자동 정지 시연은 `amr-01`을 대상으로 합니다.


### 후방 보관 구역과 추가 작업자

창고를 약 23 × 20 m로 확장하고 보관 랙 4개 구획을 추가했습니다. 작업자 4명 중 한 명은 AMR 위치에 맞춰 기존 횡단을 시작하고, 나머지 세 명은 후방 보관 통로를 순찰합니다. CCTV 04와 기존 영상 4개를 발표 화면에서 재생하고 클릭해 확대할 수 있습니다. 자동 정지에 사용하는 검출 영상은 CCTV 02입니다.

후방 랙 사이 연결 통로에는 빈 팔레트와 쏟아진 상자 7개가 놓여 있습니다. CCTV 04에서 적재물로 연결 통로가 막힌 모습을 볼 수 있습니다. 주 운반 통로의 작업자 횡단 및 CCTV 02 자동 정지 절차는 이전과 같습니다.


창고 시연 모델에는 적재 AMR 세 대와 별도 구역에서 운행하는 무인 지게차·견인형 AGV가 있습니다. 기존 공장 씬에서 작업자와 카메라 구성을 가져올 때 TIAGo, 작업대, 소형 상자는 제거합니다.


### 무인 지게차와 견인형 AGV

- **CCTV 03 · 출하 도크**에서 무인 지게차가 팔레트 밑으로 포크를 넣고, 들어 올린 뒤 도크까지 운반해 내리는 모습을 볼 수 있습니다.
- **CCTV 05 · 부품 공급 구역**에서 견인형 AGV가 부품 카트 3대를 연결해 원형 동선을 따라 움직입니다. 첫 순회에서 공급대 두 곳에 정차해 차례대로 상자를 내리고, 다음 순회 때 회수합니다.
- 두 장비는 별도 구역에서 시뮬레이션 시각에 따라 반복 구동합니다. 자연어 승인·CCTV 감지·ROS E-Stop 시연은 기존 `amr-01`에 연결되어 있습니다.
