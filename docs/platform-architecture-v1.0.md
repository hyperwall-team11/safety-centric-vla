# 가상 CCTV 기반 현장 적응형 디지털 트윈 및 온톨로지 안전 제어 플랫폼

- 작성: 최민서 (CTL)
- 검토 반영: 강영한 (CV), 2026-11-06 검토 의견
- 기준: `develop` 브랜치 코드, [`ontology-schema-v1.1.md`](ontology-schema-v1.1.md), [`backend-api-spec-v0.2.md`](backend-api-spec-v0.2.md)
- 최종 수정: 2026-11-06 (CV 2차 검토 반영)
- 관계: 개발계획서 v1.0·사용자정의서 v0.1의 시스템 구성을 가상 CCTV·디지털 트윈 구조로 확장한다. 객체명·열거값·안전 수치는 [스키마 v1.1](ontology-schema-v1.1.md)을 따른다.

> 이 문서는 **계획과 구현을 구분**한다. 각 기능의 현재 상태는 [11장 구현 상태](#11-구현-상태-2026-11-06-기준)를 기준으로 한다.

## 1. 프로젝트 개요

### 1.1. 프로젝트 목표

실제 산업 현장의 CCTV 데이터가 없는 환경에서 **MuJoCo + Three.js로 실사형 가상 CCTV 환경을 구축**하고, 이를 기반으로 CV·Ontology·ROS 2를 통합한 로봇 안전 제어 플랫폼을 개발한다.

가상 CCTV 영상을 실제 CCTV 입력과 같은 처리 과정에 넣어 작업자 탐지, 위치 추정, 디지털 트윈 재구성, 안전 검증, 로봇 제어까지 전체 파이프라인을 검증한다.

### 1.2. 핵심 아이디어

> **현장이 바뀌어도, 안전 검증 체계는 그대로.**

현장 배치(작업장 기본 구조, 로봇 모델, 금지구역)와 카메라 보정을 설정하면 **같은 검증 파이프라인을 재사용**할 수 있는 로봇 안전 제어 플랫폼을 목표로 한다. CCTV 영상만으로 현장 전체를 3D 복원하는 것은 이번 범위가 아니다.

구현할 기능:

1. **가상 산업 현장 생성:** MuJoCo와 Three.js를 이용한 실사형 CCTV 환경
2. **현장 인식:** CV를 통한 작업자 탐지 및 바닥 좌표 추정
3. **디지털 트윈 재구성:** 온톨로지 상태를 MuJoCo ② 가상 환경에 반영
4. **안전 검증:** 온톨로지 규칙 검사 및 로봇 행동 사전 시뮬레이션
5. **로봇 제어:** 검증을 통과한 행동만 ROS 2로 전달하고 위험 상황에 개입

## 2. 전체 시스템 아키텍처

```text
┌────────────────────────────────────────┐
│ MuJoCo ① + Three.js                    │
│ 가상 산업 현장 (Ground Truth)           │◀──────────────┐
│ 로봇 · 작업자 · 장비 · CCTV 영상 생성     │               │
└──────────────────┬─────────────────────┘               │
                   │ CCTV 영상 (/cctv_N/image_raw)        │
                   ▼                                      │
┌────────────────────────────────────────┐               │
│ CV: CCTV 2대 작업자 탐지·결합·위치 추정 │               │
│ 영상 + 카메라 보정 정보만 사용          │               │
└──────────────────┬─────────────────────┘               │
                   │ Sensor 상태 · Worker 스냅샷           │
                   │ · HazardEvent(금지구역 침입)          │
                   ▼                                      │
┌────────────────────────────────────────┐               │
│ Ontology: 현장 상태 관리                │               │
│ Worker · Robot · Zone(KEEP_OUT)        │               │
│ · Sensor · HazardEvent 등 관리          │               │
└──────────────────┬─────────────────────┘               │
                   │ 온톨로지 상태 스냅샷                 │
                   ▼                                      │
┌────────────────────────────────────────┐               │
│ MuJoCo ②: 디지털 트윈 재구성 (계획)     │               │
│ 온톨로지 상태만으로 장면 구성           │               │
└──────────────────┬─────────────────────┘               │
                   ▼                                      │
┌────────────────────────────────────────┐               │
│ Ontology Safety Gate                   │               │
│ 1. 규칙 검사 (5종)                      │               │
│ 2. MuJoCo ② 사전 시뮬레이션 (계획)      │               │
│ 3. APPROVED / REJECTED / ESTOP 판정    │               │
│ 4. 실행 직전 재검증 실패 시 HELD        │               │
│ 5. 판정 근거 감사 기록 (ExecutionLog)   │               │
└──────────────────┬─────────────────────┘               │
                   │ 승인된 Action만 전달                 │
                   ▼                                      │
┌────────────────────────────────────────┐               │
│ ROS 2 제어: 가상 로봇 실행              │               │
│ 위험 시 TriggerEStop / Hold State      │               │
└──────────────────┬─────────────────────┘               │
                   ▼                                      │
            MuJoCo ① 로봇 이동 ────────────────────────────┘
                 (다음 CCTV 프레임으로 순환)
```

**모듈 관계**

- CV는 현재 `PUT /sensors/{sensor_id}`, `PUT /workers/snapshot`, `POST /hazards`로 온톨로지 상태를 갱신한다. 백엔드에 별도의 `Observation` 등록 API는 없다.
- **HazardEvent 생성 주체는 CV**다(PR #41, 2026-11-05 팀 결정). 카메라 1대라도 연속 2프레임에서 금지구역 안 작업자를 보면 `CRITICAL` `WORKER_INTRUSION`을 등록한다. ONT는 규칙 판정을 담당한다.
  - 향후 대안: CV는 Observation만 제출하고 ONT가 융합해 HazardEvent를 생성. 이 경우 Observation API(백엔드), 융합 규칙(ONT), CV 전송 변경이 필요하다.
- **MuJoCo ②는 디지털 트윈 재구성과 Safety Gate 내부의 사전 시뮬레이션을 함께 담당하는 하나의 환경**이다. 승인·거부 판정과 감사 기록은 온톨로지가 단일하게 관리한다.

**안전 설계 원칙**

- 위 흐름은 행동 제안의 사전 검증 경로다. 긴급 정지는 사전 시뮬레이션 완료를 기다리는 순차 경로에만 의존하지 않도록 **별도의 신속한 정지 경로**를 둔다.
- 확인되지 않은 상태는 안전으로 보지 않는다(Fail-Closed).
- MuJoCo 기반 MVP는 실제 산업 안전 인증을 대체하지 않는다.

**미결:** 토크·관절 속도 검사는 확정 규칙이 아니다. 기준·검증 위치·스키마 반영은 ONT 담당(임성현)과 협의한다.

## 3. 핵심 설계: MuJoCo ① / MuJoCo ② 분리

MuJoCo를 **가상 기준 현장(Ground Truth, ①)** 과 **온톨로지 기반 디지털 트윈·사전 시뮬레이션 환경(②)** 으로 논리적으로 분리한다.

| 구분 | 역할 | 데이터 |
|---|---|---|
| MuJoCo ① | 실제 현장을 대신하는 가상 산업 환경 | 정확한 작업자·로봇 위치 (정답) |
| Three.js | 실사형 가상 CCTV 영상 렌더링 | CCTV 영상 프레임 |
| CV | CCTV 영상 기반 탐지 및 위치 추정 | 작업자 추정 위치·신뢰도 |
| MuJoCo ② | 온톨로지 상태 기반 재구성 및 사전 시뮬레이션 | 검증된 현장 상태·행동 검증 결과 |

### 3.1. MuJoCo ① — Ground Truth 환경 + Three.js 렌더링

- 로봇, 작업자, 장비, 장애물, 금지구역 배치
- 작업자 이동 및 로봇 동작 시뮬레이션
- Three.js에 객체 위치·회전 전달
- CV 성능 평가용 정답 좌표 저장

**Three.js 렌더링 조건**

- 장면 전체(로봇, 작업자, 장비, 바닥, 금지구역 표시)를 Three.js로 렌더링한다. 사람만 따로 합성하지 않는다.
- 작업자는 MPFB2 모델을 쓰고, MuJoCo ①의 부위별 자세에 맞춰 움직인다.
- 카메라 위치·방향·화각(fovy 60°)·해상도(640×480)를 `scenario_scene.xml`의 `cctv_1`, `cctv_2`와 같게 맞춘다. 그래야 CV의 바닥 좌표 투영이 맞는다.
- MuJoCo(z축 위) ↔ Three.js(y축 위) 좌표계 변환을 명시한다.
- 프레임마다 시뮬레이션 시각을 붙이고, 가능하면 같은 렌더러에서 작업자 분할 마스크를 함께 만든다(정답 상자 생성용).
- 시연용 안내 문구(위험 감지, 행동 차단 등)는 CV 입력 영상에 넣지 않고 별도 시연용 카메라에만 표시한다.
- 출력은 기존과 같은 ROS 2 토픽(`/cctv_1/image_raw`, rgb8, `frame_id=camera_cctv_1`)으로 발행해 CV 코드를 바꾸지 않는다.

**배경:** RT-DETR은 13.71Hz로 충분히 빠르지만, 기존 MuJoCo 마네킹은 작업자로 탐지하지 못했다(0%). 실사형 작업자로 탐지율이 개선되는지는 모델별로 다시 측정한다.

### 3.2. CV — CCTV 영상 기반 현장 인식

Three.js에서 생성한 CCTV 영상만을 입력으로 쓴다.

- RT-DETR 또는 Florence-2 기반 작업자 탐지
- 바운딩 박스와 신뢰도 추출
- 카메라 보정 정보로 바닥 좌표 투영, MuJoCo 월드 좌표로 변환
- CCTV 2대의 탐지 결과 결합
- Sensor 상태·Worker 스냅샷·HazardEvent를 온톨로지로 전송

**CV는 MuJoCo ①의 정답 좌표에 직접 접근하지 않는다.** 실제 CCTV에서 얻을 수 있는 영상과 카메라 보정 정보만 쓴다.

**신뢰도 처리**

- 모델 점수가 있으면 점수 기준을 적용한다.
- 점수가 없는 탐지기(예: Florence-2 `<OD>`)는 **연속 탐지 조건과 탐지 지속 비율**(해당 카메라 최근 5프레임 중 탐지된 비율)로 판단한다. 이 값을 `confidence`에 넣으며, 의미 해석은 ONT 검토 중이다(PR #41).
- 작업자를 못 본 것을 작업자 부재로 단정하지 않는다. 카메라가 끊기거나 결과가 늦으면 금지구역 진입 상태를 유지하고, 센서 공백은 `OBSERVATION_GAP` 규칙으로 거부한다.

### 3.3. MuJoCo ② — Digital Twin 및 사전 시뮬레이션 환경

온톨로지 상태 스냅샷을 입력받아 가상 작업 환경을 재구성하고, Safety Gate가 요청한 행동 사전 시뮬레이션을 같은 환경에서 실행한다.

- 추정된 작업자 위치 반영
- 로봇 모델과 작업구역 구성
- 로봇 행동 후보의 물리 시뮬레이션
- 충돌 및 안전거리 위반 여부 검증

**입력 제한:** MuJoCo ②는 온톨로지 상태(어댑터가 보고한 로봇 상태, CV 작업자 스냅샷, 등록된 Zone)만으로 구성한다. **MuJoCo ①의 정답 좌표는 읽지 않는다.** 정답을 읽으면 CV를 거치지 않은 검증이 되어 사전 시뮬레이션이 의미 없어진다. 정답 좌표는 3.4절의 오차 평가에만 쓴다.

**작업자 이동 고려:** MuJoCo ②는 판정 시점의 작업자 위치만 안다. 로봇이 움직이는 동안 작업자도 움직이므로, 작업자 이동 예측이나 CV 위치 오차(측정값 0.15~0.20 m)만큼의 여유 반경을 적용한다.

초기 MVP에서는 작업장 기본 구조, 로봇 모델, 카메라 위치를 미리 설정하고 CV가 움직이는 객체의 위치만 갱신한다.

### 3.4. 위치 추정 정확도 검증

| 단계 | 작업자 위치 (예시) |
|---|---|
| MuJoCo ① 실제 좌표 | (2.0, 1.5) |
| CV 추정 좌표 | (2.1, 1.4) |
| MuJoCo ② 반영 좌표 | (2.1, 1.4) |

MuJoCo ①의 정답 좌표와 MuJoCo ②의 추정 좌표를 비교해 위치 오차를 계산하고, CV 기반 공간 재구성의 정확도를 정량 평가한다.

## 4. 온톨로지 기반 안전 검증

### 4.1. 상태 관리 및 검증 요소

CV 결과가 먼저 온톨로지 상태를 갱신하고, MuJoCo ②는 그 상태를 조회해 장면을 재구성한다. VLA가 생성한 행동은 직접 실행하지 않고 `ActionProposal`로 등록하며, Safety Gate가 최종 판정한다.

**현재 구현된 규칙 (`develop` 기준)**

| 규칙 | 내용 |
|---|---|
| `SPEED` | 로봇 **이동 속도** 제한. 기본 상한 0.4 m/s, 로봇 최대 속도, 구역 속도 상한 중 최솟값을 넘으면 거부 (`rule-speed-limit`) |
| `HAZARD_STATE` | 대상 로봇 또는 목적지 구역과 연결된 OPEN `CRITICAL` HazardEvent가 있으면 거부 (`WARNING`은 차단하지 않음) |
| `KEEP_OUT` | 목적지가 금지구역(`Zone`, `zone_type=KEEP_OUT`)이거나 예상 경로가 금지구역과 교차하면 거부 |
| `OBSERVATION_GAP` | 목적지 구역을 감시하는 ONLINE 센서가 없거나 마지막 프레임이 2초보다 오래되면 거부 (Fail-Closed) |
| `SAFETY_DISTANCE` | 작업자와 예상 경로 거리가 구역 최소 안전거리(기본 1.2 m) 미만이면 거부, `estop_distance`(기본 0.6 m) 미만이면 긴급정지 |

관측 규칙은 `BACKEND_PERCEPTION_SAFETY_ENABLED=1`일 때 적용된다.

**센서 관측 공백**(`OBSERVATION_GAP`)과 **CV 관측 결과의 신뢰도**(3.2절)는 서로 다른 검사로 구분한다.

**추가 예정 / 미결**

- 경로상 충돌 위험: MuJoCo ② 사전 시뮬레이션으로 검사 (계획)
- 로봇 관절 속도·토크 제한: 미결. ONT와 기준 협의 필요

### 4.2. 하나의 Safety Gate 안에서 이중 검증

1. **규칙 검사:** 온톨로지 상태와 `ActionProposal`로 4.1절 규칙을 판정한다.
2. **물리 사전 검증 (계획):** 규칙을 통과한 후보를 같은 MuJoCo ②에서 미리 시뮬레이션해 경로 충돌·물리적 위험을 확인한다.
3. **최종 판정:**
   - 규칙 위반 → `REJECTED`
   - 긴급정지 거리(0.6 m) 위반 → `ESTOP`
   - 통과 → `APPROVED`
   - 승인 후 실행 직전 재검증 실패 → 제안을 `HELD`로 전환
4. **감사 기록:** 규칙 판정 근거, 시뮬레이션 결과, 최종 결정과 시각을 ExecutionLog에 함께 저장한다.

사전 시뮬레이션은 게이트 내부의 마지막 검사 절차이며 별도의 승인 주체가 아니다.

**Fail-Closed:** 다음 경우 승인하지 않는다.
- 검사 실패 또는 결과 미확인
- 사전 시뮬레이션 시간 초과
- MuJoCo ② 미가동

새 규칙 종류(사전 시뮬레이션)는 스키마 반영이 필요하며 ONT 승인을 거친다.

## 5. ROS 2 기반 로봇 제어

### 5.1. 승인 행동 실행 (구현, PR #30)

- 승인된 Action만 ROS 2 제어 노드로 전달
- ACK·RESULT 수신, 중복 실행 방지
- MuJoCo ①에서 로봇 이동 후 다음 CCTV 프레임 생성
- 새 CV 관측으로 온톨로지 → MuJoCo ② 상태 재동기화 (MuJoCo ②는 계획)
- 실행 결과를 온톨로지 및 감사 로그에 기록

### 5.2. 위험 상황 개입

```text
작업자 위험구역 접근
        ↓
CV 작업자 탐지 (연속 2프레임)
        ↓
CV가 HazardEvent 등록 (CRITICAL, WORKER_INTRUSION)
        ↓
TriggerEStop / Hold State
        ↓
ROS 2 로봇 정지
        ↓
위험 해제 및 재개 조건 검증
        ↓
ResumeTask 승인
```

**현재 상태:** HazardEvent가 등록되면 이후 평가와 실행 직전 재검증만 차단한다. **실행 중인 로봇을 즉시 정지시키는 경로는 미구현**이며 백엔드·CTL 후속 작업이다.

**신속 정지 경로:** 긴급 정지는 CV → 온톨로지 → 사전 시뮬레이션으로 이어지는 경로에만 의존하지 않는다. 예를 들어 검증 서버 heartbeat가 1초 동안 끊기면 CTL 어댑터가 스스로 HOLD에 들어간다([`backend-ctl-contract-v0.1.md`](backend-ctl-contract-v0.1.md)).

MVP에서는 MuJoCo의 가상 로봇으로 전체 제어 흐름을 검증하고, 향후 실제 로봇으로 확장할 수 있도록 ROS 2 인터페이스를 설계한다.

## 6. 프로젝트의 핵심 차별점

### 6.1. 실제 CCTV 없이 전체 시스템 검증

MuJoCo와 Three.js로 가상 CCTV를 생성해, 실제 산업 현장 접근 없이 다양한 위험 상황을 반복 실험한다.

### 6.2. 현장 설정만 바꿔 재사용

작업장 배치, 로봇 위치, 작업자 수, 카메라 각도를 바꿔도 현장 배치와 카메라 보정만 다시 설정하면 같은 CV–Ontology–ROS 2 처리 구조를 재사용한다.

### 6.3. 정답 데이터 기반 정량 평가

MuJoCo ①의 정답 데이터로 다음을 평가한다.

- CV 작업자 탐지율 (모델별, 카메라별, 결합 결과)
- 위치 추정 오차
- 디지털 트윈 상태 반영 정확도
- 위험 이벤트 탐지율 및 오탐률
- 위험 상황 차단 성공률
- 위험 감지부터 정지 명령까지의 지연 시간

### 6.4. 실행 전 안전 검증

VLA가 생성한 행동을 즉시 실행하지 않고, 온톨로지 규칙과 MuJoCo 물리 시뮬레이션으로 사전 검증한다.

## 7. 최종 MVP 검증 시나리오

### Scenario 1. 정상 로봇 작업

1. 가상 CCTV 환경에서 정상 작업 상황 생성 (Three.js 영상은 계획, 현재는 MuJoCo 렌더링)
2. CV가 작업자 탐지, 온톨로지 상태 갱신
3. 온톨로지 상태로 MuJoCo ② 재구성 (계획)
4. VLA가 로봇 행동 제안
5. Safety Gate에서 규칙 검사 후 MuJoCo ② 사전 시뮬레이션 (사전 시뮬레이션은 계획)
6. 승인 후 ROS 2로 MuJoCo ① 가상 로봇 실행
7. 변경된 장면의 다음 CCTV 프레임으로 순환

**검증 목표:** 정상 행동의 승인·실행 및 감사 로그 기록

### Scenario 2. 작업자 위험구역 접근

1. MuJoCo ①에서 작업자가 로봇 작업구역에 접근
2. Three.js CCTV 영상 생성 (계획, 현재는 MuJoCo 렌더링)
3. CV가 작업자 탐지 및 위치 추정
4. CV가 금지구역 침입 HazardEvent 등록
5. `TriggerEStop` 또는 `Hold State` 실행 (HazardEvent 등록 시 실행 중 로봇 즉시 정지는 미구현)
6. ROS 2 제어 노드를 통해 가상 로봇 정지 (미구현, 현재는 이후 평가와 실행 직전 재검증만 차단)

**검증 목표:** 위험 탐지부터 로봇 정지까지의 전체 안전 개입

### Scenario 3. 서로 다른 현장 구성 (계획)

- **환경 A:** 로봇 1대, 작업자 1명, 고정 CCTV 1대
- **환경 B:** 로봇 1대, 작업자 2명, 장애물 및 다른 카메라 배치
- **환경 C:** 작업 공간과 금지구역 위치가 다른 현장

**검증 목표:** 현장별 재설정 범위, 공간 재구성 정확도, 안전 규칙 적용의 재사용성

## 9. 기술적 한계 및 고려사항

### 9.1. 카메라 기반 공간 인식의 한계

현재 CCTV 2대의 탐지 결과를 결합해 단일 카메라의 가림 한계를 보완한다. 2026-11-05 측정(기존 원통형 작업자 모형 기준)에서 카메라별 탐지율은 77.9%, 88.8%였고, 두 카메라를 결합하면 457개 시점 모두에서 작업자를 탐지했다. 정밀한 3D 공간 복원은 향후 과제로 둔다.

### 9.2. Sim-to-Real Gap

가상 CCTV에서 높은 탐지 정확도를 얻어도 실제 CCTV에서 같은 성능이 보장되지 않는다. 조명, 시점, 배경, 작업자 외형, 가림을 다양화하고, 향후 실제 현장 데이터로 추가 검증한다.

### 9.3. 실시간 처리 성능

CV 추론, 트윈 갱신, 온톨로지 검증, MuJoCo 시뮬레이션에는 각각 처리 시간이 든다. 사전 행동 검증과 긴급 안전 정지를 분리해, 실시간 위험 대응이 무거운 시뮬레이션에 의해 지연되지 않게 한다.

### 9.4. 실제 산업 현장 적용의 한계

본 프로젝트는 가상 환경 기반 MVP이며 실제 산업 현장의 안전 인증을 대체하지 않는다. 실제 로봇 적용 시에는 별도의 하드웨어 안전 장치, 현장 위험성 평가, 관련 안전 표준 검증이 필요하다.

## 10. 최종 프로젝트 포지셔닝

### 프로젝트명

**가상 CCTV 기반 현장 적응형 디지털 트윈 및 온톨로지 안전 제어 플랫폼**

### 프로젝트 소개

MuJoCo와 Three.js로 실제 산업 현장과 유사한 가상 CCTV 환경을 구축하고, 현장 배치와 카메라 보정만 바꾸면 재사용할 수 있는 로봇 안전 제어 플랫폼을 검증한다.

CV가 CCTV 영상 속 작업자를 인식해 온톨로지 현장 상태에 반영하고, MuJoCo ②는 그 상태로 디지털 트윈을 재구성한다. 온톨로지 Safety Gate는 VLA의 행동 제안에 대한 규칙 검사와 MuJoCo ② 사전 시뮬레이션을 함께 관리·기록하고, 승인된 행동만 ROS 2로 전달한다. ROS 2가 MuJoCo ① 가상 로봇을 움직이면 다음 CCTV 프레임부터 같은 흐름을 반복한다.

### 핵심 가치

> **현장이 바뀌어도, 안전 검증 체계는 그대로.**

**MuJoCo ① + Three.js 가상 CCTV → CV 인식 → 온톨로지 상태 갱신 → MuJoCo ② 재구성 → Safety Gate(규칙 + MuJoCo ② 사전 검증) → ROS 2 제어 → MuJoCo ① 상태 변화 → 반복**
