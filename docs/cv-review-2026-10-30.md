# CV Observation 변환 검증 — 2026-10-30

담당: 강영한 / PR #12 (`feat/cv-observation` → `develop`).

## 실행 결과

macOS Apple Silicon, Python 3.12, MuJoCo 3.15.0에서 확인했습니다.

| 확인 | 결과 | 의미 |
|---|---|---|
| `python3 -m unittest discover -s mujoco-demo/tests -v` | 11개 통과 | 바닥 투영, 회전·높이, 잘못된 상자, SHA-256 불일치, 시간대, 신뢰도 보류·거부 |
| `python capture.py` | 안/밖 640×480 PNG와 메타데이터 생성 | 실제 MuJoCo 렌더와 이미지 크기·해시 일치 확인 |
| 새 캡처의 카메라 행렬로 알려진 바닥점 투영 후 복원 | 두 점 오차 ≤ 4.45×10⁻¹⁶ m | 카메라 축·행렬 방향을 확인하는 기하학 검사 |
| 신뢰도 없는 인공 탐지 두 건 내보내기 | 완전한 Observation 0건, 보류 2건 | Florence-2의 무점수 결과를 안전 입력으로 승인하지 않음 |
| 점수 0.7인 인공 탐지 두 건 내보내기 | 현재 backend `Observation` 모델 검증 통과 | 필수 필드 호환성 검사 |

기하학 검사 상자는 알려진 점을 수학적으로 투영해 만든 입력입니다. 점수 0.7도 계약 검증용 인공 값입니다. 위 오차와 통과 개수는 탐지기의 위치 정확도·신뢰도·재현율 측정값이 아닙니다. 이번 검토에서 Florence-2 GPU 추론을 새로 실행하지 않았습니다.

생성 파일은 `mujoco-demo/outputs/`에 있으며 `.gitignore` 대상입니다. `capture.py`와 단위 테스트로 다시 생성·확인할 수 있습니다.

## 구현 범위와 후속 작업

- 캡처와 탐지 JSON의 이미지 해시가 같고, UTC 오프셋·카메라 보정값이 있는 경우만 변환합니다. 정답 위치는 변환에 쓰지 않습니다.
- 상자 아래쪽 중앙을 바닥에 투영한 추정값이므로 발 가림·상자 오차·바닥 높이 가정의 영향을 받습니다. 실제 탐지 결과와 정답을 비교하는 위치 오차 평가가 필요합니다.
- 현재 backend에는 Observation 등록 API가 없습니다. 선택 필드 `bbox`, `position_source`는 `observation_details`에 별도 보관합니다. ONT 담당과 서버 계약을 정한 뒤 연결해야 합니다.
- Florence-2 `<OD>`는 검증된 신뢰도 점수를 제공하지 않습니다. confidence 확보, Worker·HazardEvent 갱신 및 E-Stop 연동은 완료되지 않았습니다.
- #13은 정지 이미지 추론 속도 측정, #19는 ROS 2 카메라 입력 연결입니다. 이 문서의 CPU 검증으로 두 PR의 실제 영상 성능까지 확인한 것은 아닙니다.

## 리뷰 요청 범위

ONT 담당자는 Observation 필수 필드와 무점수 보류 정책을, CTL 담당자는 카메라 행렬과 바닥 좌표 가정을 검토하면 됩니다. 이 PR은 백엔드 API나 스키마를 변경하지 않습니다.
