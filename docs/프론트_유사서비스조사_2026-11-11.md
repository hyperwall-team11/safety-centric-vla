# 운영 콘솔 유사 서비스 조사

- 작성일: 2026-11-11
- 목적: `frontend/` 운영 콘솔(대시보드·작업 요청·행동 제안·위험·현장·비상정지·판단 이력) 설계에 참고할 서비스 정리
- 근거: 각 서비스의 공식 제품 페이지·문서·보도자료. 실제 제품을 사용해 본 결과가 아니며, 일부 자료는 오래되었거나 경쟁사 비교 글이다.

## 1. 한눈에 비교

| 서비스 | 성격 | 이 프로젝트와 겹치는 부분 | 참고할 화면 |
|---|---|---|---|
| Open-RMF `rmf-web` | ROS 2 오픈소스 다중 로봇 관제 웹 | ROS 2, 평면도, 작업 요청 → 로봇 배정 | 대시보드·작업 요청·현장 |
| Boston Dynamics Orbit | Spot 플릿 관리 상용 제품 | 평면도 위 로봇·경보, 미션 지정 | 현장·대시보드·위험 |
| Formant | 로봇 원격 운영·관측 플랫폼 | 실시간 상태·영상·로그, 원격 개입 | 판단 이력·CCTV·비상정지 |
| InOrbit | 여러 회사 로봇 통합 운영(RobOps) | 사고 관리, 규칙 기반 경보, 미션 추적 | 위험·행동 제안 |
| Protex AI / Intenseye | CCTV 기반 산업 안전 비전 | 기존 CCTV로 안전 위반 탐지 | 위험·CCTV |

## 2. 서비스별 참고 포인트

### 2.1 Open-RMF `rmf-web` (구조 참고 1순위)

- Robots·Map·Doors·Lifts·Tasks 같은 작은 화면 단위로 나뉘어 있고, 작업 목록의 한 줄을 누르면 지도가 해당 로봇으로 이동한다.
- 작업은 웹 화면 또는 API로 요청하며, 디스패처가 플릿 어댑터들의 입찰(`BidNotice`)을 받아 가장 알맞은 로봇에 배정한다.
- 차이점: 이 프로젝트는 요청과 실행 사이에 `ActionProposal` 안전 검증 단계가 있다. 화면에서 이 단계를 강조하는 것이 차별점이다.
- 가져올 것: 행동 제안·판단 이력 목록에서 한 줄을 선택하면 현장 지도에서 해당 로봇을 강조.

### 2.2 Boston Dynamics Orbit (지도 중심 화면)

- 시설 평면도 위에 로봇을 실시간 표시하고, 진행 중인 경보는 운영자가 확인·해제할 때까지 지도에 남는다.
- 지도에서 도킹·기록 지점을 골라 로봇을 보낸다. 작업 요청 화면의 "지도에서 구역 클릭" 방식과 같다.
- Site View: 시점별 360° 사진으로 현장 이력을 보여 준다.
- 가져올 것: 열린 `HazardEvent`를 지도 위 위치에 표시하고 해제 전까지 유지.

### 2.3 Formant (이력·관측 화면)

- "DVR for Data": 로봇이 현재·과거에 본 센서·영상·로그를 한 타임라인에서 다시 본다.
- 브라우저 원격 조작으로 멈춘 로봇을 직접 해결한다.
- 가져올 것: 판단 이력에서 시점을 고르면 그 시점의 지도·로봇 상태를 표시. `/ws/state` 스냅샷 저장이 필요하다(Backend 작업).
- 주의: 자료 대부분이 2019~2020년 마케팅 글이다.

### 2.4 InOrbit (위험·사고 처리 흐름)

- Incident Management: 실시간 경보, 상황별 대응 조치, 진행 상태 추적.
- Advanced Incidents: 여러 조건을 묶은 규칙으로 자율 주행 예외를 처리하고, 로봇 코드 배포 없이 원격으로 규칙을 바꾼다.
- 미션 계획·추적과 "도움이 필요한 로봇" 감지.
- 가져올 것: 위험 화면에 `OPEN` → `ACKNOWLEDGED` → `RESOLVED` 단계와 처리자·시각 표시(스키마 v1.1에 이미 있는 상태값).

### 2.5 Protex AI / Intenseye (CCTV 안전 탐지)

- 기존 CCTV에 붙여 PPE 미착용, 차량 통제, 위험 행동 등을 탐지하고 규칙 엔진으로 현장별 규칙을 정한다.
- 대시보드 히트맵(사용자 리뷰), Intenseye는 3D 자세 추적·혼잡도 모니터링.
- 가져올 것: CCTV 화면에 탐지된 작업자 박스와 금지구역 침범 이벤트를 겹쳐 표시(#41과 연결).
- 주의: 대시보드 화면 자료가 거의 공개되어 있지 않고, 비교 자료는 경쟁사(Voxel) 글이다.

## 3. 적용 우선순위 제안

| 순서 | 내용 | 참고 | 필요한 작업 |
|---|---|---|---|
| 1 | 목록 ↔ 지도 연동(선택한 로봇·구역 강조) | rmf-web | Frontend만 |
| 2 | 열린 위험을 지도에 표시, 해제 전까지 유지 | Orbit | Frontend만(`GET /hazards` 사용) |
| 3 | 위험 처리 단계(`ACKNOWLEDGED`) 표시 | InOrbit | Frontend + 확인 API 여부 확인 |
| 4 | 판단 이력에서 시점별 상태 다시 보기 | Formant | Backend 스냅샷 저장 필요 |
